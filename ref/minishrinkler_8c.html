Detailed Description

Minishrinkler compression API implementation.

Author
Giovanni Bajo giova.nosp@m.nnib.nosp@m.ajo@g.nosp@m.mail.nosp@m..com

This file contains the core compression logic for Minishrinkler, providing a buffer-to-buffer compression API without any file I/O.

This implements the Shrinkler bitstream with a very simplified compression algorithm. Since the LZ coder is very basic, the compression ratio is good only on small files up to a few KiB (where the range coder itself beats standard LZ+Huffman constructs). Once the file size grows beyond that, the lack of advanced LZ techniques makes the compression ratio degrade quickly, and for large files the compression ratio is much worse than standard algorithms like DEFLATE.

struct shr_work_buffer_t

Layout structure for working memory bufferr.

All the work memory used by the compressor is described by this structure. No dynamic allocations beyond the single arena.

The match finder uses a compact set-associative hash table carved from the provided work memory. Each bucket keeps a small number (ways) of wrapped 16-bit positions.

Data Fields
shr_rangecoder_t coder Range coder context.
shr_lzstate_t state LZ coder state.
int hash_size Number of buckets (power of two)
int hash_mask hash_size - 1
int ways Associativity (entries per bucket)
int window_bits such that window_size == (1 << window_bits)
int window_size sliding window size (<= 65536)
int window_mask window_size - 1
uint16_t * buckets size = hash_size * ways; each is wrapped pos (0..mask) or 0xFFFF if empty
uint8_t * repl_index size = hash_size; round-robin replacement index per bucket
int lit_avg_events average range-coder events per literal (init ~9)

Compress data from input buffer to output buffer.

This function compresses the input data using the Minishrinkler algorithm and writes the compressed data to the output buffer. The compressed data is compatible with the official Shrinkler decompressor.

Parameters
input_dataPointer to the input data to compress
input_sizeSize of the input data in bytes
output_bufferPointer to the output buffer for compressed data
output_capacityMaximum capacity of the output buffer in bytes
work_memory_sizeSize of work memory to allocate for hash table in bytes
Returns
On success: number of bytes written to output_buffer (compressed size)
On failure: negative value indicating error -1: output buffer too small -2: invalid input parameters -3: compression failed
Note
The output buffer should be at least as large as the input data to handle worst-case scenarios where compression doesn't help. For typical data, the compressed size will be smaller than input.
The compressed output is raw data without any header, compatible with the official Shrinkler decompressor using the -d option.
This function does not perform any file I/O operations.
